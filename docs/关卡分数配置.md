# 关卡分数配置

配置入口是 `js/journey-state.js` 的 `SCORES`。每行依次为一至五星门槛，一星同时作为本关通关目标。HUD 和结算使用同一份配置，每关从零分开始。

| 本章关卡 / 尺寸 | 萤灯谷（1–5关） | 风轮镇（6–10关） | 映光庭（11–15关） |
| --- | ---: | ---: | ---: |
| 1 / 5×5 | 700 | 800 | 1000 |
| 2 / 6×6 | 1300 | 1450 | 1750 |
| 3 / 7×7 | 2100 | 2300 | 2700 |
| 4 / 8×8 | 3000 | 3300 | 3850 |
| 5 / 9×9 | 4200 | 4600 | 5200 |

## 依据与范围

- 原配置三个章节重复使用 500/800/1100/1500/1900，明显低于基础棋盘得分分布；星级还固定依赖第一关。
- 使用真实 Board 随机生成和重力规则，固定随机种子，每个尺寸分别运行 600 局随机选组、600 局即时最大组，共 6000 局。随机选组得分中位数为 935/1575/2375/3330/4530；新目标保留入门余量，逐步增加组合理解要求。
- 风轮镇额外有 6/12/18/24/30 个方块；映光庭还能通过视角拼接继续消除。两章设适度提高的目标，并为额外消除与尾盘奖励预留较高星级空间。
- 基础采样不包含旋转接触、视角可见性或人类操作难度；机关章节目标是设计估计，需要真人试玩进一步校准，不能把基础采样通过率当作它们的实测通过率。
- 消除仍为 `5 × 方块数²`；全部消完奖励 2000，剩余 1–12 块奖励 `(13-剩余数)×100`，其余为 0。
- 11 个挑战（原创造）关卡保留任务制和得分纪录，不增加分数通关门槛。代码内未开放的弹珠第 12 关不属于当前可选关卡，不修改其旧配置。

运行 `node scripts/analyze-score-balance.cjs` 可复现基础采样，结果写入 `.qa/score-balance.json`。

## 开放状态与存档

`ALL_UNLOCKED=true` 统一开放 15 个冒险关卡、11 个挑战关卡、章节和全部故事。只在实际达标/完成任务后记录通关；跳关不把前面的关卡标记完成。未通关按钮是实体灰色，仍可进入；已通关按钮内显示“已通关”。旧存档和历史低分纪录保留。
